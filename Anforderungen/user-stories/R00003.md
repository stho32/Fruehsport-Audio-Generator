# User Stories zu R00003

## US-1: Player ohne Lautstärke-Eingriffe

Als Nutzer möchte ich, dass der Player meine Audio-Lautstärken nicht mehr anfasst, damit Spotify-Streams nie in unerwarteten Zuständen zurückbleiben und ich die Absenkung selbst kontrolliere.

**Szenario 1.1: Wiedergabe ohne pactl-Aufrufe**
- Given Spotify läuft mit einem Sink-Input bei 100 % Lautstärke
- When ich `uv run Apps/podcast-player.py folge.mp3` ausführe
- Then wird die Datei abgespielt
- And es wird kein pactl-Prozess gestartet
- And der Spotify-Sink-Input bleibt unverändert bei 100 %

**Szenario 1.2: `--level` wird abgewiesen**
- Given der Player nach Umsetzung dieser Anforderung
- When ich `uv run Apps/podcast-player.py --level 35 folge.mp3` ausführe
- Then bricht der Player mit einer Fehlermeldung zu unbekanntem Argument und Exit-Code ≠ 0 ab

## US-2: Erhaltene Playlist-Funktion

Als Hörer möchte ich weiterhin mehrere Dateien und Ordner als eine Playlist abspielen, damit die Kernfunktion durch den Umbau nicht verloren geht.

**Szenario 2.1: Dateien in Aufrufreihenfolge**
- Given drei existierende MP3-Dateien `a.mp3`, `b.mp3`, `c.mp3`
- When ich `uv run Apps/podcast-player.py a.mp3 b.mp3 c.mp3` ausführe
- Then werden die drei Dateien genau in dieser Reihenfolge nacheinander abgespielt
- And der Prozess endet mit Exit-Code 0

**Szenario 2.2: Ordner alphabetisch sortiert**
- Given ein Ordner mit den Dateien `b.mp3` und `a.mp3`
- When ich den Ordner als Argument übergebe
- Then werden `a.mp3` und `b.mp3` in alphabetischer Reihenfolge abgespielt

**Szenario 2.3: mplayer-Fallback**
- Given mpv ist nicht verfügbar, mplayer ist verfügbar
- When ich eine Datei abspiele
- Then wird die Wiedergabe mit mplayer durchgeführt

## US-3: Erhaltenes Abspiel-Log

Als Nutzer möchte ich, dass das Abspiel-Log unverändert weitergeführt wird, damit bestehende Auswertungen weiter funktionieren.

**Szenario 3.1: Schema unverändert**
- Given eine bestehende Logdatei `Logs/podcast-player.jsonl`
- When eine Datei vollständig abgespielt wird
- Then werden Beginn und Ende als je eine JSON-Zeile im bisherigen Schema angehängt

## US-4: Erhaltenes Signal-Handling

Als Nutzer möchte ich die Wiedergabe weiterhin sauber abbrechen können.

**Szenario 4.1: SIGINT**
- Given eine laufende Playlist-Wiedergabe
- When ich den Prozess mit Ctrl+C (SIGINT) beende
- Then stoppt die Wiedergabe
- And das Log enthält einen „abbruch"-Eintrag für die betroffene Datei
- And der Prozess endet mit Exit-Code 130

**Szenario 4.2: SIGTERM**
- Given eine laufende Playlist-Wiedergabe
- When der Prozess SIGTERM erhält
- Then stoppt die Wiedergabe
- And das Log enthält einen „abbruch"-Eintrag
- And der Prozess endet mit Exit-Code 143

## US-5: Erhaltene Fehlertoleranz

Als Hörer möchte ich, dass eine defekte Datei die restliche Playlist weiterhin nicht verhindert.

**Szenario 5.1: Nicht abspielbare Datei mittendrin**
- Given eine Playlist `a.mp3 kaputt.mp3 c.mp3`, wobei `kaputt.mp3` nicht abspielbar ist
- When ich die Playlist abspiele
- Then werden `a.mp3` und `c.mp3` abgespielt
- And der Prozess endet mit Exit-Code ≠ 0

## US-6: Bereinigte Tests

Als Entwickler möchte ich, dass die Testsuite nur noch den reduzierten Funktionsumfang prüft, damit keine tote Testlast zurückbleibt.

**Szenario 6.1: Keine Ducking-Tests mehr**
- Given die Testsuite nach Umsetzung dieser Anforderung
- When alle Tests ausgeführt werden
- Then existieren keine Tests und Fakes mehr für AudioMixer, DuckingStrategy oder pactl
- And alle verbleibenden Tests (Unit, Integration, E2E) sind grün
- And die Coverage über alle Ebenen liegt bei ~90 %

## US-7: Nachvollziehbare Entscheidung

Als Entwickler möchte ich die Entscheidungshistorie im ADR-Bestand nachvollziehen können.

**Szenario 7.1: ADR-0001 als überholt markiert**
- Given ADR-0001 (Polling-Ducking mit Adapter-Abstraktion)
- When diese Anforderung umgesetzt ist
- Then existiert ADR-0001 weiterhin und trägt den Status „überholt" (superseded) mit Verweis auf das neue ADR
- And das neue ADR dokumentiert Entscheidung und Begründung (Spotify setzt Lautstärken bei Titelwechseln zurück, manuelle Absenkung durch den Nutzer)

**Szenario 7.2: README ohne Ducking-Versprechen**
- Given die README nach Umsetzung dieser Anforderung
- When ich den Abschnitt zum Podcast-Player lese
- Then wird kein Ducking und kein `--level` mehr beschrieben

## US-8: Manuelles Werkzeug bleibt

Als Nutzer möchte ich mein bisheriges Ducking-Skript weiter nutzen können.

**Szenario 8.1: spotify-ducking.sh unangetastet**
- Given `~/.claude/scripts/spotify-ducking.sh`
- When diese Anforderung umgesetzt ist
- Then ist die Datei byte-identisch unverändert
